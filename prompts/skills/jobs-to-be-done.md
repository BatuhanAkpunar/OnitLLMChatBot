## Purpose
Capture the progress a user is trying to make in a given situation, independent of any solution. A job persists even as products change, so it is a more stable foundation than features or demographics.

## Structure
Write each job as: **When [situation], I want to [motivation], so I can [expected outcome].**
- **Functional** job: the practical task.
- **Emotional** job: how they want to feel (in control, safe, smart).
- **Social** job: how they want to be seen.
- **Current hire/fire**: what they "hire" today to do this job and why they would "fire" it.
- **Success measure**: how the user judges the job done well (speed, certainty, effort).

## Method
1. Strip the solution out of the request; ask what progress the user is buying.
2. List 3-5 jobs, then mark the one job the product will be the best in the world at.
3. Note the trigger that starts the job; that trigger is where the product must show up.

## Anti-patterns
- Jobs written as features ("the job is to click export").
- Only functional jobs; emotional and social jobs often decide adoption.
- Treating a persona as a job.

## When NOT to use
For pure technical or infrastructure work with no end-user choice, JTBD adds little.
